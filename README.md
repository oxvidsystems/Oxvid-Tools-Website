# Oxvid Tools

A React + Vite conversion of the original single-file "Toolworks" HTML site,
rebranded as Oxvid Tools: 146 client-side utilities (PDF, image, text,
developer, calculator, SEO, finance, generator and color/design tools) across
a proper multi-page app.

## Stack

- **React 19** + **React Router 7** for the app shell, routing and pages.
- **Vite 8** for dev/build tooling.
- Plain CSS (`src/styles.css`), extracted from the original site with no
  changes to visual design.
- **Vercel Routing Middleware** (`middleware.js`) for real 404s and serving
  prerendered HTML to crawlers/link-unfurl bots.

## Project structure

```
src/
  core/
    engine-core.js      Shared helpers, tool/category data, and the generic
                         render engines (calculator/text/image workspaces)
                         used across multiple categories.
    engine-<category>.js  One file per category (pdf, image, text, dev,
                         calc, seo, finance, gen, color) — just that
                         category's tool implementations + its own
                         DISPATCH map. Fetched on demand by
                         ToolWorkspace.jsx (dynamic import) only when a
                         tool from that category is opened, instead of
                         bundling all 145 tools up front.
                         Generated by scripts/split-engine.mjs via static
                         AST analysis of the original monolithic engine —
                         re-run it if engine internals need to change by
                         hand (rare; usually just edit the category file
                         directly).
  components/           Header, Footer, Layout, SearchBox, ToolCard,
                         CategoryCard, ToolWorkspace, PlatformBadge, Section,
                         BrandMark
  pages/                 Home, AllTools, Categories, Category, ToolPage,
                         About, Contact, Privacy, Terms, NotFound — each
                         lazy-loaded (React.lazy) as its own chunk
  hooks/                 useTheme (light/dark), useVisualEffects (scroll
                         reveal, counters, card tilt), useSEO (per-page
                         title/description/canonical/OG/Twitter/JSON-LD)
  data/staticCopy.js     About/Privacy/Terms copy
middleware.js            Vercel Routing Middleware: real 404s for unknown
                         paths, and serves a prerendered snapshot to
                         detected bots/crawlers on valid routes
middleware-routes.generated.js
                         Flat list of every valid route; imported by
                         middleware.js. Generated by
                         scripts/generate-routes-manifest.mjs
public/_prerendered/     Static HTML snapshot of every route (from
                         scripts/prerender.mjs), served only to bots
public/sitemap.xml       Generated by scripts/generate-sitemap.mjs
```

Routing uses real paths (`/tool/word-counter`) via `BrowserRouter` rather
than the original's `#/...` hash routes — `vercel.json` adds the SPA rewrite
this requires.

## Why a bot-only prerendered snapshot?

This is a client-rendered SPA: the raw HTML response for any route is the
same empty shell until React runs. Google renders JavaScript, so it sees
real content eventually — but most other consumers (WhatsApp/Slack/Discord
link previews, many SEO tools, older crawlers) never execute JS, and would
otherwise see only the homepage's generic title/description for every page.

Rather than adopt full SSR (a much larger change for a 146-page bare Vite
SPA), `middleware.js` runs on Vercel's edge for every request and:

1. **Rejects unknown paths with a real HTTP 404** (checked against
   `middleware-routes.generated.js`) — previously every bad URL returned a
   soft 200 because `vercel.json`'s SPA rewrite matched everything.
2. **Serves a prerendered HTML snapshot** (`public/_prerendered/...`,
   produced locally by `scripts/prerender.mjs` with Playwright and
   committed as ordinary static files — Vercel's build never needs a
   browser) to requests whose User-Agent matches a known bot/crawler.
3. **Passes every other request straight through** (`next()`), so real
   visitors always get the exact same SPA experience as before — no
   hydration, no behavior change, zero risk to the interactive site.

Whenever tool content changes meaningfully, re-run:

```bash
npm run build       # also regenerates sitemap.xml + the routes manifest
npm run prerender   # requires Playwright + a Chromium binary available
```

and commit the refreshed `public/_prerendered/` output.

## Scope note

Of 146 registered tools, 145 have real, working implementations (matching
the original site). The one exception — a live HTTP status checker — needs
a server-side proxy a static site can't provide, and is honestly marked
"Coming soon" rather than faked, exactly as in the source file.

## Development

```bash
npm install
npm run dev       # start dev server
npm run build     # production build (outputs to dist/)
npm run preview   # preview the production build locally
npm run prerender # crawl the build and refresh public/_prerendered/ (needs Playwright)
npm run lint      # oxlint
```
